# 无硬件验收与实机待办

当前软件已经包含主流程、传感器、能量策略与预算、无线确认、电脑接收和测试工具。下面的“软件检查”不替代实际外设验证。真实取电电源、绕组、PCB和最终机械尺寸仍依赖实物参数。

## 1 无实体板子时运行哪些命令

在工程根目录执行：

```powershell
python -m pip install -r desktop/requirements.txt
python -m pip install -r tests/requirements.txt
python tools/check.py --build
python tools/release.py
```

前两条只安装电脑运行/测试依赖；后两条不烧录、不访问DeepSeek、不连接硬件。`check`失败就保留完整错误，先不打包。`release`会重新构建并更新六份预编译固件；修改源码后不能仅提交旧HEX。

## 2 检查范围

| 部分 | 电脑上可验证 | 仍需实物验证 |
|---|---|---|
| 六个构建配置 | Arm GCC编译、链接、内存上限 | SWD下载、F5、LED、串口 |
| 温度与振动计算 | CRC、负温度、分辨率低位、去均值RMS、饱和 | 1-Wire实际时序、传感器精度、采样节拍和量程 |
| 电压与预算 | 换算边界、余量、任务准入、周期上下限 | 内部基准/分压比、电容真实容量与ESR、每个任务实际耗能 |
| 无线驱动 | 假HAL下正确/错误/过期ACK、有限重试、UART/AUX失败、最终休眠 | E22完整型号、固件版本、天线、空中时序、接收成功率和功耗 |
| 电脑上位机 | 假串口输入、随机分片、坏帧过滤、ACK写回、CSV记录 | 真实USB-TTL、驱动、端口占用、断线重连操作 |
| I2C恢复 | 源码编译与超时路径准备 | 实际SDA/SCL锁死、9脉冲和STOP是否释放设备 |
| 休眠与恢复 | 时钟配置/中断函数编译、纯逻辑测试 | RTC精度、STOP唤醒、看门狗、掉电启动和整机电流 |
| DeepSeek | 文件筛选、默认预览、不执行输出 | 账号余额、模型可用性、真实请求 |
| 结构模型 | 浏览器交互与布局说明 | 实物尺寸、干涉、公差、绝缘、防护和装配 |

## 3 新增的无线确认怎么用

普通`wireless`只检查本地AUX流程；`wireless_ack`等待电脑接收端回传的10字节ACK，且节点号、boot、seq和CRC全部匹配才返回成功。超时最多再发一次，同一个逻辑数据包重试时保持同一序号；电脑会再次确认，CSV保留重复接收事实。

```powershell
python tools/project.py build wireless_ack
python tools/project.py flash wireless_ack
python desktop/monitor.py --port COM6 --ack --timeout 45 --out-dir logs
```

这三条只在板子到货后用于联调。接收端必须补接**USB-TTL TX→接收端E22 RXD**；原来的E22 TXD→USB-TTL RX继续保留。双方都是9600/8N1、透明传输、匹配的无线参数。不按发射功率最大值盲目配置。3秒确认超时是初始参数，需按实际空速、包长和模块时序调整。

ACK说明电脑应用已经校验了对应数据帧，不证明传感器数值正确、数据已经长期备份或通信具备身份认证。确认帧也只有CRC，没有密钥认证。默认fixed/adaptive保持无ACK，避免把未测定的接收等待耗电混入两种能量策略的对比。

## 4 能量预算的初始假设

| 参数 | 初始值 | 含义 |
|---|---:|---|
| STORE_CAPACITANCE_MF | 1000mF | 按1F计算，必须核实实物 |
| ENERGY_RESERVE_MJ | 100mJ | 保护电压以上继续预留的任务余量 |
| TEMP_COST_MJ | 5mJ | 一次温度任务估算 |
| VIBRATION_COST_MJ | 10mJ | 一次振动任务估算 |
| RADIO_COST_MJ | 150mJ | 一次无ACK发射任务估算 |
| ACK_RADIO_COST_MJ | 400mJ | 一次带接收等待的发送尝试估算，重试另计 |
| SLEEP_POWER_UW | 200µW | 整机休眠功率估算；Blue Pill实际值可能明显更高 |
| MAX_ADAPTIVE_PERIOD_S | 300s | 自适应周期上限 |

`energy_policy`先执行电压保护和滞回；`energy_budget`在adaptive版增加余量和任务准入，再根据前后电容能量变化、估算任务消耗计算输入功率并平滑，调整下一轮间隔。正常基础15秒、低能量基础60秒，可延长到300秒。输入不足时延长周期，保护态不发包。

这些数字是**可运行算法的待校准初值，不是本组实测结果**。电压变化还受电容误差、漏电、ESR和负载影响，估算输入功率不能替代仪器测量。硬件欠压保护仍需独立设计。

上位机默认通信超时900秒，覆盖最长300秒周期；固定15秒/普通无线联调时可设`--timeout 45`。保护态不发包，电脑只能看到超时，无法凭空分辨节点没电还是无线中断。

## 5 板子到货后的验收顺序

1. `bringup`：供电、SWD、LED与30行HELLO。
2. `sensors`：温度、振动、ADC逐个接；断线后有效位变化，恢复接线后可重新读数。
3. `wireless`：先单向接收，保存LIVE记录。
4. `wireless_ack`：补接电脑端TX，验证确认、暂时断开接收端、有限重试与恢复。
5. `fixed`：RTC/STOP/看门狗、周期功耗和无线电源掉压。
6. 校准真实电容和每项任务耗能后运行`adaptive`，与fixed做同工况对比。
7. 最后接真实取能/储能链，断开节点一切外供电，验证冷启动、续航与恢复。

调试时每次只改变一项。保留固件配置/提交号、实际接线、原始日志、测量仪器与量程，不以模拟曲线代替硬件数据。
